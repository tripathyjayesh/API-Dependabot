- subscriptions POST: new billing_mode (object) added; default billing semantics changed to flexible (i.e., integrations that need classic must opt into classic). (OpenAPI diff evidence)

Confirmed consumer code affected in this repository (evidence)
- Subscription schedule creation: createSchedule reads phases[].iterations and sums them. Affected method: createSchedule(...) and SchedulePhase record using int iterations. [E2] and [E8]
- Promotion code creation: createPromotionCode expects a top-level PromotionCodeRequest.coupon and returns that value. Affected method and PromotionCodeRequest record. [E2] and [E8]
- Subscription GET / discount handling: getSubscription returns DiscountResponse with an expanded Coupon; consumer expects discounts[0].coupon.name. Affected method and DiscountResponse/Coupon records. [E3] and [E8]
- Checkout Session GET: getCheckoutSession returns CheckoutSessionResponse with a currency_conversion field and test expects currency_conversion.amount. Affected method and CheckoutSessionResponse record. [E3] and [E8]
- Subscription creation billing semantics: createSubscription assumes classic billing (controller returns "classic (assumed by this Basil-era consumer)"). Affected method and SubscriptionRequest usage. [E3] and [E8]

Migration recommended by release documentation (repo docs + release notes)
- Change phases[].iterations -> phases[].duration (use duration.interval and duration.interval_count). [E5]
- Replace top-level promotion coupon with promotion.type=coupon and promotion.coupon when creating promotion_codes. [E5]
- For discounts in responses, stop expecting expanded coupon objects at discounts[].coupon; instead use discounts[].source and, if you need the coupon object, fetch/expand the coupon from the source as appropriate. [E5]
- Stop reading currency_conversion from checkout session responses; read the new currency field and remove code that expects currency_conversion. [E5]
- If you require the old "classic" subscription semantics, explicitly pass billing_mode.type=classic when creating subscriptions (Clover defaults to flexible). [E5] (also summarized in README/upgrade instructions) [E1][E4]
